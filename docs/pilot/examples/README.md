# Synthetic examples of the weekly growth report — not measurements

Everything in this folder is **SYNTHETIC**: invented rows written to exercise
the report after the W6 correction pass. None of it was observed, none of it is
progress, and none of it may be copied into a real report. Real reports are
generated by the owner from production, dated the Sunday the week ended
(`docs/pilot/weekly-review.md`).

| File | What it shows |
|---|---|
| [`2026-11-02-synthetic-report.md`](2026-11-02-synthetic-report.md) | The whole report on the fixture database and fixture log/readings: the assistance gate with **STOP**, **UNKNOWN**, **ok**, **no activity** and **not gated** rows; the eligible population; local weeks and a partial current week; `_now` columns; the October checkpoint **met** on a dated reading; the log with a **missing** week, **missing** cells, a rejected Monday row and a rejected duplicate |
| [`synthetic-acquisition-cases.md`](synthetic-acquisition-cases.md) | The acquisition half alone on five inputs: **complete** (met), **partial** (unverified, never missed), **failing** (missed), **missing** (unverified and open), **contradictory** (not judged) |
| [`w6-reproduction.md`](w6-reproduction.md) | Each of the six review findings reproduced on the `82cb92f` code, with the corrected answer and the test that holds it |

Regenerate both reports (the full one needs the sandbox chain,
`tests/sim/sandbox/apply.sh`):

```
CS_PG_BIN=<psql dir> node tests/pilot/fixtures/render-examples.mjs
```

The inputs: `tests/pilot/fixtures/w6-fixtures.sql` (the database rows — every
golfer is "Synthetic N" at example.com), `w6-synthetic-log.csv` and
`w6-synthetic-readings.csv`.
