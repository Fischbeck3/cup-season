**How to read severity here.** P0 = violating it blocks a goal (App Review, security, money honesty, immutability of the record, or a change that cannot ship without an entry). P1 = a major collision or a canon contradiction the design phase will trip on. P2 = a term/ruling that will be re-litigated if not named. P3 = polish/staleness in the canon documents.

**SAW vs INFER.** "SAW" = read in the file at the cited line. "INFER" = my reading of what it implies. Marked inline where the distinction matters.

## Section 2 — Flows in this area

There are four "flows" a designer will actually run against this area. For each: goal · friction · unnecessary complexity · confusing terminology · dead ends · redundancy · missing feedback · delight.

### Flow A — From a law to a screen (how a string reaches both clients)

- **Goal.** A designer wants to know what a screen must say (e.g. the stage word, the money line) and where to change it.
- **Friction (SAW).** The law and its home are in different documents: the ledger line is a law in `brand-canon.md:64-76`, its home is `index.html:4418` and `MoneyCopy.swift:28`; the stage words are a law in D120/D136 (`decision-log.md:4232-4240`, `:4400-4403`), their home is `STAGE_LABEL`/`Stage.label`. Nothing in canon lists producers; you learn them by reading D201 (`:5449`: "Where a producer exists and is bypassed, the copy is wrong. There is not one exception in the audit.").
- **Unnecessary complexity.** Two clients, two producers per law, kept in step by tests only for stages (preflight 20) and bands (db-check 17); the ledger constant has no gate at all (`MoneyCopy.swift:10-19` explains why).
- **Confusing terminology (exact strings).** The middle tab is "Post" on both bars (`index.html:3911`, `MainTabView.swift:209`) but the Guide still calls it "⊕" (`Cup-Season-Guide.md:87`), the IA blueprint calls it "Golf" (`ia-blueprint.html:169`), and the web's `#view-record` header calls itself a hub about "Golf" (`PostCoverView.swift:90`: `CSPageHeader("Golf", …)`). Four names for one door in canon alone.
- **Dead ends.** `docs/ux-overhaul-2026-09-04` does not exist at tip (`ls` failed) — the brief for this overhaul is not yet in the repo, so there is nothing for a superseding entry to cite by path.
- **Redundant actions.** The four places are described in six places: preamble `:13-15`, `#obOrient`, `OrientationCopy`, `GuideCopy.sheets["places"]`, `Cup-Season-Guide.md:80-92`, `IOS-002 §2`. D82 already flagged "a second place the model is described and must be kept true" (`:2876`).
- **Missing feedback.** No index of "ruled vs built". D115, D117, D128, D130 (client), D131, D132 (definition half), D134 are RULED and UNBUILT at tip (verified by grep, Section 3E) and nothing in the log header says so.
- **Delight opportunity.** D201's own diagnosis: put every new law in a producer with a preflight sibling; the redesign can *add gates* (a `CS_LEDGER` presence check, a ledger-drift grep for "never held"/"never the money") rather than only strings.

### Flow B — From a recommendation to a shipped change (the process)

- **Goal.** Ship a UX/IA change that touches copy, a migration, and both clients.
- **The path (SAW).** (1) Log the entry BEFORE building, in the format "Current mechanic · Problem observed · Recommendation · Principle served · Expected user benefit · Tradeoffs (+ CONFLICT where one exists)" (`decision-log.md:23-25`; `CLAUDE.md:37-42`). (2) Wait for "build it" (`CLAUDE.md:20-21`). (3) Migrations timestamp-named, never edited after they run; a fix is a NEW migration (`CLAUDE.md:29-31`; `ship.sh:60-61`). (4) Every new client-called function: `grant execute … to authenticated` + `revoke … from public, anon` (`CLAUDE.md:113-125, :186-190`); a profiles column needs its own `grant select (col)` (`:192-198`). (5) After a push that adds/re-signs a function: refresh `packages/db/contract.psv` from the query in its header, then `node tools/build-db.mjs` (`ship.sh:65-66`; `build-db.mjs:1-9`) — it writes `rpc.ts` AND `Rpc.swift` (`preflight.mjs:313`). (6) `node tests/preflight.mjs` must pass 21/21 (`ship.sh:32-37`). (7) The OWNER runs the two independent deploys — `supabase db push` (DATABASE) and `git push` (CLIENT → Netlify), plus `supabase functions deploy <name>` when an edge function changed (`CLAUDE.md:55-67`); `./tools/ship.sh` is the prompt and asks for each separately (`ship.sh:7-12`). (8) Native builds are a third artifact: `tools/ios-archive.sh --upload` (IOS-027, `DECISIONS.md:267`); a missing RPC on the phone is "a version mismatch to surface, never a silent downgrade" (`IOS-002:188`); `app_flags.min_ios_build` gates a forced update.
- **Friction.** Rule 3: "Design passes and structural builds ride separately" (`CLAUDE.md:32-33`) — the redesign must be sequenced as separate commits from any migration wave. Rule 6: native work runs locally; remote sessions keep migrations/specs/web (`:49-51`).
- **Unnecessary complexity.** Deploy-skew rule: new RPC args need a client retry that drops the field on any error; new SQL params must default (`CLAUDE.md:77-80`, `:196-198`) — every new field the redesign adds to `native_home()` pays this.
- **Confusing terminology.** "Level 3/5" in the log means IA/UI; a UX entry that renames a tab is level 3, a copy entry is level 5, and the preamble says lower levels may not contradict higher (`:20`). The brief is owner-authored at levels 1–2, so it *can* amend level 3 — but only through an entry that names the conflict.
- **Dead ends.** The "Supabase Casa" MCP is a different project (`CLAUDE.md:281-286`); read prod only via `supabase db query --linked` from the repo root.
- **Missing feedback.** ship.sh reports "unknown, never clean" when the CLI cannot look (`CLAUDE.md:75-76`) — a remote session cannot confirm what is owed.
- **Delight.** The Stop hook already answers "what do I owe?" silently (`.claude/settings.json:40-51`).

### Flow C — Is this ruling still open? (what the redesign must check before re-proposing)

- **Goal.** Avoid re-proposing what is already ruled (the prior audit's 135 issues were remediated as D111–D139; much was built since).
- **Friction (SAW).** The log records BUILT status inline and inconsistently: D121 says "BUILT 2026-09-02 on iOS … The web row is still owed" (`:4243`); D129/D130/D138 carry long "BUILT … the data only" parentheticals (`:4324`, `:4334`, `:4456`); D115/D117/D128/D134 carry nothing and are unbuilt (grep, Section 3E). The remediation plan's theme files (`docs/audit/blind-ux-2026-08-29/plan/t1…t7.md`) are PLANS, not status.
- **Dead end.** Some D-numbers are missing headings (D162–D164, D167, D169–D172) and D125a, D152a/b, D153a/b, D157a, D200a, D60a, D103a/b exist as sub-entries — `grep '^### D<n>'` does not find them all.
- **Recommendation.** The overhaul's first artifact should be a ruled-vs-built ledger for D111–D139 and D176–D221 (Section 3E carries the ones verified here).

### Flow D — Two clients, one product (parity vs divergence)

- **Goal.** The redesign changes the phone (shipping) and the web (declared reference).
- **Friction (SAW).** IOS-018 (`DECISIONS.md:179-189`, logged as D100 `:3633-3658`) rules "the phone builds everything the web has … in the web's own copy and behaviour. Only after parity is real does the ecosystem question get asked: what the web should be as a standalone product next to the phone (a later decision, not this one)." The brief IS that later decision, but no entry has opened it. Meanwhile the phone has moved past the web on Home (D121 row, D176 lead card, D217 fold, D218 doors, D203 paging) and the log records each web half as "owed" or "a web task" (`:4243`, `:4334`, `:4456`, `:5671`).
- **Unnecessary complexity.** Every ruling is now built twice; every copy law needs two producers. D201: 57 of 165 voice findings were "the same thing said twice on one screen" (`:5433`).
- **Confusing terminology.** `IOS-011` says "⊕ is a full-screen cover opening on the post form" (`DECISIONS.md:127`); the D110 addendum reversed that ("the ⊕ … now ALWAYS open the cover", `:4116-4119`) and IOS-011 was never amended.
- **Missing feedback.** No statement of which client is the reference *now*. CLAUDE.md `:301-303` still says "The web client is the behavioural reference; the phone owns operating the league, the desk owns authoring it (IOS-007)" — superseded by IOS-018/D100, uncorrected.
