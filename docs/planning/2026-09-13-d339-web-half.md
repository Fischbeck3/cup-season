# D339 · the web half — inventory, reconciliation and the first checkpoint

Date 2026-09-13. Status: **proposal for the owner and Codex; nothing built.**
Branch `claude/d339-web-half`, based on Codex's audit commit `49714a9`
(which sits on the release evidence `eca1b3c`). The frozen release is
unchanged: `main` and the live site stay at `963d0e6`.

**Why this exists.** The owner opened cupseason.app and found it "miles behind"
the phone. The live site is current (`963d0e6`, the tip of `main`), and the
signed-in surfaces run today's code — so the gap is not a stale deploy. It is
that **D339, the DesignV1 beta identity, shipped natively only.** Its two
commits (`a4714cf`, `246b77a`) touched zero lines of `index.html`, and
`docs/design-designv1-implementation.md` says so: *"no web look behavior …
changed."* D234 says every change has a phone half and a web half; D339 was
left at half. The door — the first thing anyone sees — still carries the
previous identity.

This document does three things, kept apart on purpose:

1. **§1** inventories every D339 surface on the phone against its web
   counterpart, and says what the web shows today.
2. **§2** reconciles that with Codex's [mobile Safari sprint brief](2026-09-13-mobile-safari-experience-sprint.md)
   and its [audit](../reviews/2026-09-13-mobile-web-experience-audit.md): the
   **functional repairs stay functional**, on their own branch, and are not
   blocked on any brand ruling.
3. **§3** names D339's unresolved decisions explicitly and recommends the
   smallest first identity checkpoint that needs the fewest of them.

Governing: D234 (two clients, one product, two shapes), D339, IOS-081,
`spec/brand-canon.md` (2026-09-11 notes), UI_SYSTEM §5.1 / LINT-28 / §14 /
§16A.1, rule 3 of CLAUDE.md (design passes ride separately from structural
builds).

**What the web can reuse without redrawing anything.** The pennant is authored
once in `brand/candidates/testflight-pennant/source.json` and generated by
`tools/build-beta-mark.sh` into `generated/`: `mark-one-color.svg`
(currentColor — the exact form the web's `.hdrmark` rule wants),
`mark-dark-ground.svg`, `mark-light-ground.svg`, the horizontal lockups, and
`icon-16/32.png` optically reinforced without contour detail. `brand/` is
already in `stamp-version.sh`'s served allowlist. So #1, #3 and #7 are an
inline of a generated SVG, not new artwork; the rule stays *edit the source and
the generator, never the outputs.*

**What must not be copied.** The owner superseded literal DesignV1 screens
twice (returns to 791, then 762; `docs/design-designv1-implementation.md`):
*"DesignV1 is a source for identity, contours, photography and artifacts, not
product wireframes."* The web keeps its utility UX — the one-step door with
email → code, league code, resend, terms; the desk sidebar and two-column body
(UI_SYSTEM §14). Nothing in §1 changes a control, a route, a rule or a fact.

## 2 · Reconciliation with the mobile Safari sprint

Codex's brief is a **function and hierarchy** sprint; this is an **identity**
sprint. They touch the same file and must not touch the same lines at the same
time, so:

| | Functional repairs (Codex's brief) | Identity (this plan) |
|---|---|---|
| Branch | `claude/mobile-safari-experience` from `origin/main` (as the brief says) | `claude/d339-web-half`, its own commits, rebased after checkpoint A is reviewed |
| Governs | audit IDs MW-01…MW-07 | §1 rows 1, 3, 5, 7 first; 6, 8, 9 later |
| Needs an owner ruling first? | **No.** Every MW item is a verified defect or hierarchy fix under existing decisions | **Yes — one** (§3, decision 0); the rest are sequenced around the open ones |
| Mark | *"Preserve the production mark pending an explicit brand decision"* (MW-07) | is that decision's web execution, once taken |

**The verified functional findings stay actionable and stay separate.** They
are true on the live site today and none of them waits on a brand ruling:

- **MW-01 · Compete → START SOMETHING is dead.** `#cmpStart` exists only in
  markup (`index.html:5309`); nothing binds it to `openIntentSheet()` (`:26582`).
  Reproduced by Codex through the visible link at 390 and 320. First commit of
  checkpoint A, with a regression that clicks the rendered control and asserts
  the sheet.
- **MW-02 · the duplicate Home wire.** *"You are the one to catch."* appears
  twice in a row with no differentiating context — seen independently in the
  release operator's 1440 capture of the review account's Home. Deduplicate
  identical facts; if the rows are different leagues, keep both and name the
  league.
- **MW-05 · squad copy in solo posting.** The posting paragraph (`:4824`) says
  *"Your best few each month count toward your squad"* in a solo league. Use
  the existing format-aware counting copy. The release's `putTheCardDown`
  behaviour (date reset, draft ownership, retry) is preserved.

Where the two sprints meet on the same markup, the functional sprint goes
first: MW-07 touches the narrow header, MW-03/MW-04 reshape the Compete and
season heads. Identity checkpoint I-1 therefore takes **only the door and the
sidebar brand block** (rows 1, 3-wide, 5), which no MW item edits; the narrow
header mark (row 3-narrow) follows once MW-07's header lands.

**Explicit, as asked:**

- **Welcome / boot** — one surface on the web (row 1 covers row 2). Copy and
  mark change; the door's controls, flow and the `v23 · <sha>` caption do not.
- **Masthead** — mark swap only, wide first (sidebar), narrow after MW-07.
- **Brand copy** — a single `CS_BRAND` producer (`name`, `tagline`, `extended`,
  `standfirst`) read by the door, the `<meta>` and `og:` tags and the artifact
  footer. The ledger sentence (*Cup Season keeps the ledger; the money moves
  between friends*) is product copy, not brand copy, and stays where §16A.1
  puts it.
- **Shared artifacts** — one `csArtifactFooter(ctx, w, h)` drawn by all five
  generators, mirroring `CSArtifactFrame`: mark, CUP SEASON, tagline,
  `cupseason.app`. Real round exports keep the actual played date. `og-image`
  waits with the icons (row 9).

## 3 · D339's unresolved decisions, and the smallest first checkpoint

Named in D339 itself, `docs/ios/DECISIONS.md` IOS-081 and `spec/inbox.md`
(2026-09-12 rulings owed). None has been ruled. Each is stated with its web
consequence so the owner can rule once for both clients.

| # | Decision | Where it stands | Web consequence |
|---|---|---|---|

| **1** | **LINT-28 — is the pennant reserved to the tab band and icon, or is it the brand's mark wherever the brand signs?** (D339 Open 1). ## 4 · What this plan does not do

- Does not rule on any of decisions 0–4; it asks.
- Does not copy a DesignV1 composition; the web keeps its utility UX and its
  desk shape.
- Does not touch the frozen release, `main`, the live site, the database, Edge,
  the native app, the token system or the mark source/generator.
- Does not fold the functional repairs into an identity commit, or the reverse.
