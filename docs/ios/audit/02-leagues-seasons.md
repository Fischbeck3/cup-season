### 1.4 Loading / error conventions worth carrying to native

- Every league load is skew-tolerant: retry a narrower select on ANY error (never message-sniff — the 42501 "permission denied for table profiles" lesson; 14294, 14219, 14383).
- `bootStep` breadcrumbs + 8 s watchdog (`Boot stalled at [step]`); `#errbar` persistent error surface.
- No spinner states for league data — the header flips to "Loading the room…" (14204) and sections render progressively as each fetch lands; hero/pulse re-render when `league_pulse` and `season_scenarios` arrive.
- Empty states are prose in scoreboard voice (all caps mono) and always route somewhere (D27/D94).

**`v_squad_standings`** (baseline:1411): `season_id, squad_id, points` = Σ squad members' counting points + Σ `season_adjustments.points` for that `squad_id`. A row per squad, empty squads at 0. No rank column; the client sorts (14374) and `enter_cup_final` orders by `points` alone.

## 4. Business rules with citations

### 4.1 Client-observed rules (see also §4.2+)
- Presets are bundles (§8, D48): allowance/verification/penalty index off `state.preset` (11836–11838, 14890–14893); counting cap and floor are exposed under "Customize" and may diverge from the preset. Server validates only the CHECK constraints — no bylaw-combination validation exists.
- Season = N whole weeks from any first-tee weekday (§14.0 v1.1): `ends_on = starts_on + durWeeks*7` (7089); `season_months` stored coarse and clamped 3..12 (3796) — a 2-week season stores `season_months=3` and is otherwise unrelated to the real dates.
- Cup Final window = last 27 days ending `ends_on` (7078, 11778); client foreshadows it; points-table leagues show no cut line (4576) and no Final line.
- Endgame dial flippable by the Pro until the window opens — client (11911) and server (`set_league_finish`) agree.
- Structure minimums are guidance (`STRUCT_MIN`, toast 11832); the server enforces min-4 / no-empty-squad / no-unassigned at `start_season` (D58).
- Pot: default 60/25/15; champion absorbs cent remainders (11487); $0 = no pot surfaces at all (D70).
- Invites only after lock (D40); any member can share the link (17057); the Pro is always the creator (`renderProChip`), the role moves only via `transfer_pro`.
- Membership has no phase gate server-side (`join_league`), so late joiners can appear mid-season and even post-complete; the client's forming copy and `openLockShare` seat math assume pre-draw joins.

### 4.2 Formation (§15, D54, D58)
- Two LIVE engines: **blind draw** (`randomize_squads`, smallest-squad dealing, one server-side shuffle, board reveal) and **Pro assign** (`assign_player`). Captains are a side effect (`limit 1` unordered) — there is no `set_captain` RPC and `role='captain'` is never written.
- UNBUILT: **snake draft / live draft with pick clock** (Pro roadmap per §15). `start_draft`/`make_pick`/`undo_pick` exist but: `drafts.type` CHECK excludes `'random'` so `start_draft` fails on a default league; `rounds_count` never set (stays 3 → 4-squad league drafts 12 and deadlocks with `'draft is full'` while `start_season` refuses the leftover pool); no clock; no phase flip into draft; no duplicate-pick guard; restart reshuffles under existing picks; zero client call sites (`renderDraft` snake board is DEMO-ONLY, 5427). Wizard markup offers only Blind draw/Assign (3272), but `state.draftType` accepts `snake|live` (14167) and a stored value would dead-end at `randomize_squads`'s "Pro assign" error.
- UNBUILT: **D54 scheduled draft-night reveal** — zero matches for `draw_at|reveal|draft_night` in migrations.

### 4.3 Season scoring, caps, floors, byes, close, Cup Final, tiebreaks, trophies

One line each, server side, with where it lives.

- **§2.2 bands** — `cup_points(pvi)`: 12 at pvi ≥ 3 · 9 at ≥ 1 · 7 at > −1 · 6 at ≥ −3 · else 5 (baseline:247); pvi = round(index_at_post × allowance/100, 1) − differential, allowance read from `league_settings` at query time (`v_rounds_ranked`); 9-hole = ⌈points/2⌉ and 0.5 floor credit (§2.4). The 12-point ceiling is the anti-sandbag device; the 5 floor is why a posted 98 still scores.
- **§2.3 bonuses** — retired (D7/D48); no bonus column anywhere; `season_scenarios` relies on that for its ceiling.
- **§3.1 counting cap** — `month_rank ≤ coalesce(counting_cap, 999)` per member per CALENDAR month in both standings views; displacement is automatic because nothing is stored. `counting_cap` NULL = unlimited.
- **§3.2 floor** — assessed only by `close_month` at the turn of the month, only for `squad_members`; `deduct` = −5 × ceil(short), `forfeit` = −(that member's counting points that month), `none` skips the loop (`20260716180000:21`). §3.2's "Pro: 0–2 byes" is not built — exactly one bye per member per season.
- **D14 auto-bye** — the season's one bye fires itself on the FIRST breach (`bye` row, 0 pts, welcome-back post); floors bite from the second; Pro pre-grant/revoke via `set_member_bye` (one bye per season, resolved through the squad seat). Named CONFLICT with principle 1 logged and accepted.
- **§3.3 squad score** — `v_squad_standings` = Σ counting points + Σ ledger; "season total = Σ months" is implicit (the view never groups by month; `close_season` derives months via `date_trunc`).
- **§14.0 season shape** — whole-week season from any weekday (v1.1): client writes `ends_on = starts_on + 7·weeks` (7089), i.e. 7w+1 inclusive days ending on the START weekday, not the eve; the server never validates dates (`seasons` has no CHECK beyond NOT NULL). Floors waived in partial edge months = `is_partial` in `close_month` (blanket). §14.1's late-joiner "before the 15th" proration is UNBUILT — a late joiner in a full month faces the whole floor (and, via `v_rounds_ranked`, gets full retroactive credit).
- **§14.2 month close** — cron `run_month_closes` at 00:10 Phoenix on the 1st (`20260712110000:22`), one `close_month` per active season: ledger rows with reasons → `month_closed` sentinel → "JULY CLOSED — LEDGER POSTED" post. The cron is pinned to Phoenix; `seasons.timezone` is honored only by the season-close grace. The standings snapshot spec'd for the close is the separate Sunday `snapshot_week` cron, not part of `close_month`.
- **D53 podium ceremony** — NOT built server-side; the close post is still one line (the board-voice pass `20260727160000` re-created `close_month` verbatim).
- **§14.3 Cup Final window** — `[ends_on − 27, ends_on]` (28 days); opened by the tick at 00:20 Phoenix the first day `today ≥ ends_on−27` and only when `finish='cup_final'` (`20260722100000:167`); seeds = top 2 (`squads2` → both, seed 1 `head_start=10`; solo → top-2 members) into `cup_finalists`; finalists scored on window-only counting points + head start (`close_season`, `20260724230000`). Non-finalists keep their full-season totals; Points King is full-season.
- **§14.3 tiebreak ladder** — in `close_season` only (never on the seeding cut): score → months won (strict-greater vs every other contender, over the FULL season's months even in cup mode — the spec's "h2h months" reading is not window-scoped) → best single month → fewest rounds used → `random()` recorded as rung `'coin flip'` (the flip is logged by name, not streamed or seeded). Spec §9's older ladder (squad PvI → h2h → coin) is superseded by §14.3 and NOT what runs.
- **D4 foreshadowing** — client-only (`#statFinal` 9406, cut row 4576, `climbCut` 4273, `renderScenarioLine`); no server surface. The top seed "keeps something" = the squads2 +10 only; in squads3/4 the leader carries nothing into the Final.
- **D24 scenarios** — `season_scenarios` clinch/eliminate only under the generous ceiling `roster × months_left × cap × 12`; K per dial; `locked` once `status='cup_final'`; the client's LOCKED/OUT badges and "X more locks a seed" come straight from `rows[].clinched/eliminated/needs`.
- **Endgame dial (migration 008 = `20260716170000`)** — `league_settings.finish` default `cup_final`; `points_table` → the tick never opens a Final and `close_season` crowns from the full-season views (squads: `v_squad_standings` incl. ledger; solo: `v_individual_standings`); `set_league_finish` is locked once `status='cup_final'` or `today ≥ ends_on−27`; flipping mid-season posts "THE PRO SET THE FINISH…". A league whose `finish` was `points_table` at `ends_on−27` and is later flipped cannot be — the lock is date-based, so the Final can never open late.
- **§14.4 / D66 close** — fires when `now() > local midnight after ends_on + grace_hours (48)` in `seasons.timezone`; because the tick runs once at 00:20 Phoenix, the practical close is 00:20 on `ends_on + 3`. Stores champion/runner-up ids, `champion_score`, `runnerup_score`, `tiebreak_rung`, `points_king_member_id`; two natural-case posts; `award_season_trophies` → `trophies` + `season_payouts` (D67); `leagues.phase='complete'`. Rounds posted inside the grace with `played_on ≤ ends_on` count; rounds backdated into the window AFTER the close still appear in every view (status `complete` is in `v_rounds_ranked`'s filter) but cannot change the stored crown — so the live table and the stored result can disagree forever.
- **§14.4 pot** — pot = `buyin_cents × count(league_members)` at close time, split by `payout_*`, regardless of who actually paid (`buy_ins.paid` is ignored by both `close_season` and `award_season_trophies`); "settle between yourselves" (D39: tracked, never held).
- **§14.5 / D41 run it back** — no server object: `runItBack` (14177) copies bylaws into a NEW league via the normal wizard; `seasons.number` is always 1 (14946); no `previous_league_id`, no "defending champion" linkage; the old league stays `complete` forever (undeletable, D71/`delete_league`).
- **D71 cancellation** — free league: immediate delete; money league: unanimous approval (`count(votes) ≥ count(members)`) then `cancel_league_now` snapshots paid members into `cancellation_notices` and deletes; no `cancelled` status, no board post, rounds survive (they belong to profiles).
- **D66 ceremony gating** — once per member per season via `localStorage cs_cer_<season>` (11520) — device-local, so it replays on every new device/app install.

## 5. Season lifecycle state machine

Two columns carry the lifecycle and nothing keeps them in lockstep: **`leagues.phase`** (`setup → draft → season → complete`; CHECK baseline:1108) is what the CLIENT routes on, **`seasons.status`** (`active → cup_final → complete`; CHECK baseline:1293) is what the ENGINE (cron) routes on. A `seasons` row exists only from lock onward, and it is born `active` even though the league is still forming. The client never reads `status` to decide CUP FINAL — `isCupFinal()` (11778) is `finish==='cup_final' && phase==='season' && now ≥ ends_on−27`, i.e. date arithmetic that happens to agree with the tick.

## 7. Edge cases & landmines

Each of these is either observed in HEAD or a direct consequence of the code above; the iOS build must not reintroduce assumptions the server does not make.

1. **`close_month` is callable by any signed-in user (regression).** `20260718172300:44` revoked it for exactly this reason; `20260727160000:340–341` re-granted it. A member can `rpc('close_month', {p_season, p_month: <current month>})` on the 15th: floors are assessed on half a month, auto-byes get burned, penalties land, and the `month_closed` sentinel then makes the cron's real close a no-op. Fix is a one-line revoke migration (or an `is_commissioner`/`auth.uid() is null` body gate); native must never call it.
2. **`leagues.commissioner_id` never follows `transfer_pro`.** `is_commissioner()` reads `league_members.role`, but `delete_account` reads `leagues.commissioner_id`: the ORIGINAL creator can never delete their account while the league has other members ("Hand it off" — they already did), and the NEW Pro can delete their account freely, cascading their membership away and leaving a league with no `role='commissioner'` row (every Pro RPC then fails for everyone). Also `leagues_read` grants the creator SELECT forever via `commissioner_id`.
3. **Two lifecycle columns, no lockstep.** `seasons.status='active'` from the moment of lock while `leagues.phase='draft'`; the engine runs on `status` and never checks `phase`. A league stuck in `draft` (Pro never tapped Start) still gets month-close posts, snapshots, a Cup Final and a crowning — with empty squads at 0 points. Native must derive "is the season actually live" from `phase='season' AND today ≥ starts_on`, and "Cup Final" from `status='cup_final'` (not dates, which is what the web does at 11778).
4. **There is no server event at first tee.** `kicked_off` is dead (the tick branch was lost in `20260716170000`). Anything the phone wants to do "when the season starts" (push, hero flip) must be computed from `starts_on` locally; there is no post, webhook, or column change to subscribe to.
5. **Late joiners score retroactively and face full floors.** `v_rounds_ranked` joins by `profile_id` over the whole date window — a golfer joining in week 6 brings every round since `starts_on` with them, changing standings the moment `join_league` commits; and §14.1's "before/after the 15th" proration is unbuilt. `join_league` has no phase gate at all — joins land in `cup_final` and even `complete` seasons (the new member then appears in `v_individual_standings` and the pot count).
6. **The pot ignores who paid.** `close_season`/`award_season_trophies` compute pot = buy-in × ALL members; `buy_ins.paid` is bookkeeping only. A member who never paid still inflates everyone's "what you're owed" line in the ceremony.
7. **Seeding has no tiebreak; the crown does.** `enter_cup_final` orders `points desc limit 2` — a tie at the cut (or for the squads2 +10) is decided by Postgres row order. `close_season` applies the four-rung ladder and stores the rung; native must not show a tiebreak explanation for seeds.
8. **"Fresh slate" is invisible in the views.** During `cup_final`, `v_squad_standings`/`v_individual_standings` keep showing full-season totals; the window-only finalists' race exists only inside `close_season` (and roughly in `season_scenarios.rows[].rank` while `locked`). The web's "CUP FINAL · fresh slate" copy sits over a table that is NOT fresh — native has to compute the window race itself from `v_rounds_ranked` (`played_on ≥ ends_on−27`, `month_rank ≤ cap`, + `head_start`) or ask for a server view that does.
9. **The stored result and the live table can diverge.** Rounds backdated into the window after the close still flow through the views (status `complete` is included). Trophy Room must render from `seasons.champion_*`/`_score`/`tiebreak_rung` (D66) — never re-derive.
10. **Week numbering has three definitions.** Server snapshot: Sundays, `floor((today−starts_on)/7)`, `total = ceil((len+1)/7)`; client `currentWeek()` (11790) from the real first-tee weekday; `seasonWeeks` (14421) uses `round`. With a Wednesday first tee the "Wk 3" chip and the `week_no=3` snapshot describe different spans. Pick the server's definition for movement chips and label it honestly.
11. **Month machinery is calendar + Phoenix.** Caps and floors are per CALENDAR month (`date_trunc('month', played_on)`), not per season-month; the crons fire at Phoenix midnight; `seasons.timezone` only moves the 48-hour close. A Denver league's "month closes at midnight" is 00:10 Phoenix = 01:10 Denver in winter — fine — but its round dated by local `played_on` is what counts, so a round played after 23:00 on the 31st MST is next month's if the device says so. Always send `played_on` as a local calendar date, never a UTC instant (CLAUDE.md landmine, same family).
12. **Solo leagues have no floors, no byes, no ledger.** `close_month` iterates `squad_members`; `set_member_bye` resolves through a squad seat ("No active season for that member"); `v_individual_standings` has no adjustment term. Yet `league_pulse` and the wizard's floor stepper both present floors to solo leagues. Native should hide floor UI when `structure='solo'` (or the server should assess them — open question).
13. **`season_format` default is `'hybrid'`.** Only the client's lock write sets `'points'`; a league whose settings row was created any other way (run-it-back copy is fine, but a future native create that skips a field is not) will silently pay +15/month to the top squad.
14. **The ledger is write-only from the client's point of view.** Reasons exist (`season_adjustments.reason`) but nothing reads them; the "ledger net" on the squad receipt is subtraction. The Pro can also INSERT `override` rows via RLS with no post — an invisible score change, contra §16.
15. **`trophies` unique key is per calendar YEAR.** Two seasons closing in one year (a 13-week spring + a 13-week fall) cannot both mint "Champion" for the same golfer in the same league; `season_payouts` (keyed by season) still record both — the case and the earnings disagree.
16. **`randomize_squads` demands `draft_type='random'`; `assign_player` demands nothing.** A stored `snake`/`live` value (legal per CHECK, reachable via `state.draftType` 14167) dead-ends the draw with a "Pro assign" message while Assign still works — native should treat `draft_type ∉ {random, assign}` as `assign`.
17. **Formation captains are `limit 1` unordered**, re-backfilled on every draw; a captain can change under a member between two loads. Do not key anything on `captain_member_id`.
18. **`delete_league` cascades the board, the ledger and the snapshots; `rounds` survive.** A member's round history outlives the league; the round post (`posts.round_id`) does not. Native round history must come from `rounds` (profile), never from posts.
19. **`start_season` requires ≥4 members even for `squads2`**, while the wizard's `STRUCT_MIN` says 4 for squads2 and only toasts; solo has no minimum. The failure message is the only place the number is stated — surface it before the tap.
20. **The D66 ceremony "once" flag is device-local** (`cs_cer_<season>` in localStorage); on a phone it will replay per install. Either accept it or persist "seen" server-side (nothing exists for that).
21. **Lock is five client writes, not a transaction** (§1.3 C + the HEAD `ReferenceError` bug). If the phone ever locks, it must be prepared to find a league with `locked_at` set, a season row, and `phase` still `setup` — or wait for a `lock_league` RPC (D98 says lock is desk work, so probably: don't lock from the phone, but DO render the half-locked state sanely).

## 8. Web-specific / clunky — what native should do differently, what must stay intact

**Do differently (opinionated):**
- **Read `seasons.status`, not the calendar, for the Cup Final.** The web derives CUP FINAL from `ends_on−27` and `finish` (11778) and never reads `cup_finalists`. Native should treat `status='cup_final'` + `cup_finalists` as truth, show the seeds with their `head_start`, and compute the window race from `v_rounds_ranked` — the one place the "fresh slate" can actually be seen (§7.8).
- **Subscribe to lifecycle posts, not to state.** Every engine transition (Final opens, month closes, season closes, bye kicks in, floor missed) is a `system` post on the league board and nothing else; the phone's realtime channel on `posts` (dedicated client, per CLAUDE.md) is the only push-shaped signal. The first-tee moment has no post at all (§7.4) — schedule a local notification from `starts_on`.
- **Stop computing awards on the client.** Points King / Most Improved / Iron Man are client-derived from `indRows` (11250) and can disagree with `seasons.points_king_member_id` once the season closes. Native should read the stored king for complete seasons and label the in-season versions as projections.
- **One phase enum.** Collapse `(leagues.phase, seasons.status, today vs starts_on/ends_on−27)` into a single derived `LeagueState` (`forming | drafting | preTee | live | cupFinal | complete | cancelled(deleted)`) at the data layer and route every screen on it. The honest split is *authoring* (wizard, lock, assign, overrides) on the desk vs *operating* (draw, start, bye, buy-in, finish dial) plus *reading everything* on the phone.

**Must stay intact regardless of surface:** identity checked at the database (every write above is a definer RPC — do not re-implement a gate in Swift/TS and trust it); rounds immutable, `delete_round` only; D39 money posture (a ledger, never a wallet — no pay/collect affordance); the eight-digit OTP and code-only email flows; the `anon` endpoints for the join/claim funnel; `played_on` as a local calendar date; `season_scenarios`' honesty rule (never invent a clinch on the client); D66's rule that the ceremony reads stored columns.

## 9. Open questions

1. **Is `close_month`'s `authenticated` grant (`20260727160000:341`) live in prod?** If the RPC snapshot (`contract.psv:45`, refreshed 2026-08-26) reflects prod, yes. Needs a revoke migration before any phone build ships a client that can be pointed at it.
2. **Should `transfer_pro` update `leagues.commissioner_id`?** Two definitions of "the Pro" exist (`role` vs `commissioner_id`) and `delete_account`/`leagues_read` use the wrong one. Decision needed before native hardcodes either.
3. **Should the engine gate on `leagues.phase`?** A league that never leaves `draft` still gets crowned. Either the tick should skip `phase <> 'season'` seasons, or `start_season` should be what flips `seasons.status` to `active` (and the lock should insert a `pending` status that does not exist yet in the CHECK).
4. **Does anyone want the first-tee post back?** `kicked_off` is dead; the phone will want a push at first tee. Server post + push (one line in the tick) or local notification only?
5. **Solo leagues and floors** — assess them (member-level ledger, which `v_individual_standings` would then have to sum) or hide the dial for `structure='solo'`? Today the wizard offers a floor that will never fire.
6. **Cup seeding tiebreak** — apply the §14.3 ladder (or at least `pvi`) at `enter_cup_final`, or accept row order? It decides the +10 in a squads2 league.
7. **Late joiners** — keep retroactive credit (simple, arguably generous) or implement §9/§14.1 provisional scoring and the 15th-of-month floor waiver? Native copy ("your rounds since Sep 5 already count") depends on the answer.
8. **Pot vs paid** — should the close use `buy_ins.paid` (pot = what was actually collected) or the bylaw (pot = what was promised)? D39 says tracked-never-held, which reads as "promised", but the ceremony then tells a paid member they are owed money by someone who never paid in.
9. **Ledger reversibility** — §14.2 promises "reversible via the log"; nothing can UPDATE/DELETE `season_adjustments`. Is a `reverse_adjustment(p_id, p_reason)` RPC (posting to the board) wanted before the ledger is shown on the phone?
10. **Trophy uniqueness per year** — change the unique index to `(league_id, profile_id, placement, season_id)`? Blocks two-seasons-a-year leagues, which D41 run-it-back actively encourages.
11. **Week definition** — should `snapshot_week` run on the league's first-tee weekday (a per-season cron key or a tick-driven check) so `week_no` matches `currentWeek()`? Otherwise the phone should label snapshots by date, not week.
12. **Multi-season continuity (D41 deferred)** — a `previous_league_id` / `seasons.number > 1` design would let the phone show "defending champs" and keep one board across seasons. Is that in scope for the native arc or still Pro Shop?
13. **`season_format='hybrid'` column default** — flip the default to `'points'` (D48 retired hybrid) so a missing field can never turn the +15 on?
14. **D53 podium** — still wanted? If yes it is server copy in `close_month`; the phone would render it as the month's episode-ender.
15. **Where does the ceremony "seen" flag live for a multi-device user?** Nothing server-side records it; a `season_views` row or a profile jsonb would let phone + web agree.
