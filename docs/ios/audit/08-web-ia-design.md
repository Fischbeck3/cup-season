## 0. How the client is put together (what a native rebuild is replacing)

- One HTML file. `<style>` runs lines 37–2478; a pre-paint theme script at 2479–2510; markup 2512–3720; then three script blocks — classic (3630–3720 error bar + SW registration), classic app (3722–~13900), and the `type="module"` Supabase block (~13900–17767).
- There is **no router**. Every screen is a `<section class="view" id="view-…">` (2792–3620) and `switchView(v)` (4131) toggles `.active` on exactly one of them, toggles `.tab`/`.navitem` highlight, and calls `window.scrollTo({top:0})`. Nothing is pushed to `history` — `grep history.pushState` finds zero hits; the only `history` calls are `replaceState` to strip URL params (17354, 17564, 17586). **Browser/OS back never navigates inside the app.**
- Entry into a view happens three ways: the tab bar / sidebar (`data-v`, bound at 4182), any element with `[data-go]` (bound once at load, 12724) and direct `switchView()` calls from renderers. Aliases inside `switchView` keep old routes alive: `feed→home`, `cal→schedule`, `pot→hub+setRoomSeg('pot')`, `board→openBoardFull()` (a dialog, not a view), `draft` during setup → `wizard` with a toast (4132–4141).
- Sub-navigation inside the Clubhouse is a segmented control (`#roomSeg`, 3373) toggling `.roompane` panes via `setRoomSeg` (4116). The "Schedule" segment does not toggle a pane; it calls `switchView('schedule')` (4120) — a destination since D93.
- Overlays: the door (`#onboard`, 2549), the bottom sheet (`#sheet`, 3710 / `openSheet` 11580 — 57 call sites), the full-screen board (`#boardFull`, 3610), the finish ceremony (`#finish`, 3691), the stamp (`#stamp`, 3689), the toast (3687), the install nudge (3703), the debug error bar (3629), and two URL-param takeovers rendered as fixed divs (`?share` at 17393, `?unsub` at 17371).
- State: a single classic-side `state` object (3768) seeded with demo scenery (`demo:true` by default — 3772) and a module-side `window.CS` (user, profile, memberships, league, members, squads). Sign-in flips `state.demo=false` (17093). `document.body.noleague` (17091, CSS 1873/1886) is the one real CSS gate; the `.league-only` class used 21 times is **inert** — "LOOKS like a gate but has no CSS rule and no JS behind it" (10776–10778).

## 2. Navigation model

- **Tab bar (phone, <960px)** `nav.tabbar` (3621): **Home · Clubhouse · [⊕] · You**. CSS grid of 3 lanes (2031); the ⊕ (`data-v="record"`, labelled "Post", `aria-label="Post a round"`) is `position:fixed` and floats above the bar's centre, 42px ember-gradient circle with glow (982–987, 2032–2049), label suppressed (`font-size:0`). Active tab = ember text + 4px dot (2041). Icons are inline 21px stroke SVGs; labels mono 10.5px uppercase (1607–1612).
- **Sidebar (desktop ≥960px)** `.side` (2734): Home · Post a round · Clubhouse · You + league/meta foot. Tab bar hidden at ≥960 (1606).
- **Header** `.hdr` (2757): sticky, blurred, safe-area top. Left: 🔍 "Find golfers" (`openFindGolfers` 13853). Right: the Tracer mark + "Cup Season" wordmark button → `switchView('home')` (13861). League name/week live in the Clubhouse header and Home, not here (2765).
- **Back**: explicit `.backlink` anchors only (`← Home`, `← Golf`, `← You`; 785). No history integration, so hardware/gesture back leaves the site; Escape closes the sheet only. Every `switchView` scrolls to top — no scroll restoration.
- **Hierarchy as lived**: Home → (hub | record | stats) are peers; `post`/`play` are children of `record`; `people` is a child of `stats`; `schedule` is a child of Home *and* a Clubhouse segment; `wizard`/`draft`/`event` are reached contextually. The board is a modal from anywhere (`data-go="board"`).
- **Deep links / URL params** (all consumed then stripped with `replaceState`):
  - `?join=CODE` (17560): stores `cs_code`, resolves league name via anon `league_by_code`, warms the door copy "You're invited to {name}. Enter your email and you're in."; joins on this boot (signed in) or right after the golfer card (`resumeAfterProfile` 17313).
  - `?claim=TOKEN` (17583): stores `cs_claim`; `claimPendingRound` (17588) tries `claim_round` then `claim_scan_round`; a still-live round keeps the token and toasts "They're still out there — your card lands here when the round finishes" (D86).
  - `?share=TOKEN` (17393): terminal public card, no app boot; Netlify edge function rewrites OG tags per token (`netlify.toml` 43–47, D77/D78).
  - `?unsub=TOKEN` (17371): one-click unsubscribe takeover (D68).
  - `?exit` (17634): sign out + reload (test hatch). `?debug` / `?debug=off` (3635) error bar. `?forge` (2505) replays the full splash.
  - `#error=…&error_code=otp_expired` (17347): auth failure copy.
- **Universal links**: `.well-known/apple-app-site-association` exists and is copied into `dist/` by `stamp-version.sh` (41–44), served as JSON no-cache (`netlify.toml` 50–54). It maps **only** `/?claim=*` and `/?join=*` to app id `3F7BK4WVH8.app.cupseason.ios`. `?share=` is deliberately not claimed (a share page should open in the browser for strangers). The current iOS artifact is a Capacitor shell whose `server.url` is `https://cupseason.app` (`ios-wrapper/capacitor.config.json`) — i.e. a remote-web wrapper, not a bundled app — and the web code already contains a Capacitor APNs bridge (`nativePush`, `apnsToken`, `syncNativePush`, `enablePush` at 13983–14050) that calls `register_device_token(p_platform:'ios')`.
- **Persistence keys** (localStorage): `cs_theme`, `cs_forge`, `cs_code`/`cs_code_name`, `cs_claim`, `cs_last_league`, `cs_oriented`, `cs_nudge_done`, `cs_debug`, `cs_apns_token`. `cs_last_league` picks which membership `enterLeague` loads on boot (17327).

**How the IA got here (the decisions to cite).** The blueprint is `spec/handoffs/ia-blueprint.html` (July 2026): four questions, four slots — Home "What happened?" · Compete "Where do I stand?" · ⊕ Golf "I'm playing" · You "How am I doing?" — "FOUR SLOTS · THE GOLD ⊕ IS A VERB, NOT A PLACE". It killed the five-tab bar: the Calendar tab ("a mostly-empty month grid never earned a tab"), the People tab ("the People Picker *component* survives untouched — it was always the real asset, not the tab"), the Pot page ("money is league context, never global"), the quick-post card on Home ("top pilot complaint, twice") and standalone Wolf/live pages. Migration phases IA P1 One Home → P2 League Room → P3 You → P4 ⊕ triptych → P5 retire People, all visible as comments in the markup (2797, 2860, 2987, 3335, 3456, 3510). Shipped names differ from the blueprint's (Compete → **Clubhouse**, the ⊕ is labelled "Post"). D38 (`spec/decision-log.md:1068–1097`) scoped the League Room calendar to `mine || shared_league || tagged_me` and made Home "the richer social/planning surface". **D93** (`spec/decision-log.md:3276–3326`, "Three things that were sections become places") promoted Schedule and Buddies to routable views and gave the board a route to the dialog it already had, while insisting "**NAV UNCHANGED — and that is the point.** The blueprint's four slots (Home · Clubhouse · ⊕ · You) stay exactly as shipped… The quadrant Home was considered and rejected". Its own recorded tradeoff: "Deep links to a routed view do not restore the Clubhouse segment state they came from" (`:3325`) — a symptom of having no navigation stack.

**The motion canon behind the code** (`spec/motion-brief.md`, `spec/motion-dossier.md`, `prototypes/motion/`):

(The V5 Forge show runs ≈5.6s on the *first* visit only; the once-per-device stamp honours the ceiling on every later launch.)
- The ten concept cards (`spec/motion-dossier.md:112–245`) and what shipped: **C1 The Last Ten Feet** (tracers converge on one cup — shipped, evolved into the Forge) · **C2 The Drop** ("your round arrives the way a putt does" — shipped as the finish screen's ball) · **C3 The Flip Board + the Roar** ("a lead change is NEWS posted by hand… Gold paints the new leader only after the flip lands: earned, then painted" — shipped as SF-6 `sfFlip` + `csRoar`) · **C4 The Engraver** ("the Claret Jug is engraved the same afternoon it's won", ~3.2s, "once-a-season ceremony, the length is deliberate" — shipped `csEngrave`) · **C5 The Month Seal** (canted 1.4° "like a hand set it"; reduced motion keeps the cant because "it's information — a hand set it — not motion" — shipped `csSeal`) · **C6 The Pot Odometer** ("the books ABSORB money", digits only roll upward — shipped `csOdo`) · **C7 Draft Night — the Card Turns** (cost L, not shipped) · **C8 Seeds Lock**, **C9 Your Number Mints**, **C10 The Taunt Lands** ("Never gold, never longer than 350ms — it's banter, not honor") — card-only. ## 5. PWA / service worker / offline — and the native equivalent

**As built**
- `manifest.webmanifest`: standalone, portrait, `#0C0D0F` background/theme, 192/512/maskable icons, start_url `/`.
- `sw.js` (97 lines): network-first for navigations with `/` cached as fallback; cache-first for same-origin static assets; **never intercepts cross-origin** (Supabase, Google Fonts); cache name keyed on the build SHA (`__CS_VERSION__`) so each deploy retires the previous cache; `push` → `showNotification`; `notificationclick` focuses/navigates an open tab or opens one. Registered after `load` (3678–3684). `Cache-Control: no-store` on `/sw.js` (`netlify.toml`).
- So "offline" = the last HTML shell renders, then every data call fails and `humanError` says "Connection hiccup". No data cache, no queue, no `navigator.onLine` handling — with two pockets of tolerance in the live round: a `drainAbandons()` retry queue for scrapped rounds (9355) and an "undo edits this phone made while offline" path in the pencil (7571).
- Install: `beforeinstallprompt` is captured and **held** until an earned moment (`csEarnInstallNudge` after first post / landing in a league; 12740–12764); iOS gets a Share → Add to Home Screen instruction sheet. `display-mode: standalone` detection.
- Push: web push via VAPID when installed; on the Capacitor shell the same toggle drives APNs (13983–14050). Web push needs the installed PWA ("Notifications need the installed app: add to home screen first").
- Version identity: `v23 · <sha>` in the door caption and the settings sheet.
- Realtime: one league channel `lg-<id>` on a dedicated `rtClient` (14698) for the board; a `live-<round>-<code>` channel for group-phone scoring (14753).

**What native needs instead**
- A real offline story: cache the last-known league/home payloads (memberships, standings, feed, schedule) so a cold launch on the course shows yesterday's table rather than a spinner; queue the quick post and the pencil's hole entries locally and replay them (the server already tolerates retries via idempotent RPC shapes and deploy-skew fallbacks).
- APNs end-to-end (the RPC and the toggle semantics already exist), notification deep links that route to a screen — today every payload carries `url:'/'` (sw.js comment), so notification→screen routing is unbuilt on both sides.
- Universal links for `?join`/`?claim` (AASA already published) plus in-app handling of `?share` in a web view or SFSafariViewController; Sign in with Apple (`.btn.apple` style exists at 464 but no button is in the markup — email-code is the only door).
- Build stamp: keep a visible build/commit line in Settings (rule 2 in CLAUDE.md), since the caption is the deploy diagnostic today.
- Haptics: `navigator.vibrate([10,38,10])` becomes a real impact haptic (expo-haptics / `UIImpactFeedbackGenerator`) on the stamp/finish and the reaction tap.
- Theme: `cs_theme` → an app-level appearance override with the same three options (Charcoal default, Light, Match device), sourced from `packages/tokens/tokens.ts`.

## 6. Accessibility state

- **Type**: everything is px; no Dynamic Type equivalent. 84 font-size declarations are ≤10px (tile labels 8.5px, streak tags 9.5, tab labels 10.5, legends 10) — mono uppercase with wide tracking makes those *look* crisp but they are below any iOS minimum (11pt caption is the floor; body is 17pt). Inputs are 16px purely to defeat Safari zoom. Native must map: eyebrow → `.caption2`/`.footnote` mono, stat value → `.title2` mono, hero → `.largeTitle` serif, body → `.body`/`.subheadline`.
- **Contrast** (dark theme, approximate): `mut` #8E979E on `bg0` ≈ 6.2:1 (passes); `dim` #5C646B on `bg0` ≈ 3.1:1 and on `bg1` ≈ 2.8:1 — **fails AA for text**, and `dim` is the colour of every eyebrow, tab label, table head, backlink and `.fine` paragraph. `brand` ember #E8622C on bg0 ≈ 5.0:1 (ok); `gold` on bg0 ≈ 9:1. Light theme `dim` #8C9992 on #EFF2EE ≈ 2.7:1 — same problem. The tokens file records that `focus` was tuned to 3:1 on paper, so contrast has been considered for rings but not for the dim tier. This is a known, filed finding: design review 07-20 **F1** flagged the light CTA at ~3.2:1 *and* the `--dim` AA fail (cross-referenced in `spec/friction-register-2026-07.md:151–157`); the CTA half was fixed and re-run under D76 ("dark ink on the light-theme ember (#C94E1F) is ~3.0:1 — fails AA. White ink clears 4.5:1", 2004–2007), the `--dim` half is still open.
- **Reduced motion**: 22 media blocks + JS checks (3855, 3887, 3956) — the splash rests on the logo, split-flap/odometer/stamp/climb/pulses all switch off. Well covered.
- **Semantics**: `role="dialog" aria-modal` on door, sheet, board, finish (2549, 3710, 3610, 3691); `aria-live` only on `#obStatus` and the post calc (2 uses); `aria-label` ×61; `role=` ×19; `:focus-visible` rules ×31 (`--focus` ring). A MutationObserver stamps every `.tap` row with `tabindex=0 role=button` and maps Enter/Space to click (4185–4204). Escape closes the sheet. Body scroll lock `lockBody` (5339). `color-scheme` follows theme so native pickers match.
- **Hit targets**: `.btn` 46, `.mini` ≈38 tall, inputs 44, tab 46, ⊕ floor 44 (F2 fix, 2036). Some `.mini` chips and the `✕` dismissers are under 44.
- **Gaps for native**: no VoiceOver ordering intent (the DOM order is the reading order, and the desktop board/standings split re-flows by CSS grid); charts (the climb, sparkline, gauge) have `aria-label` but no data-table alternative; emoji reactions have text labels (`RXLABEL`) which should become accessibility labels; markers as identity need names announced ("The Saguaro").

## 7. Honest critique — what is web-shaped, what is cramped, what must carry over

**Frame first — what the phone is for.** D98 (`spec/decision-log.md:3493–3577`, 2026-08-26) killed the Capacitor wrapper ("the wrapper's ceiling is permanent… the surfaces were never named" — the web client "has been a desktop app for months and nobody called it one": draft 117 client refs, roster 97, wizard 56, ledger 49, 13 `min-width:960px` breakpoints) and named three surfaces (`spec/native-arc.md:14–23`): **Phone** (Expo / React Native, iOS first) owns *live scoring, posting a round, the board, push, standings read*; **Desktop** (React rewrite) owns *the wizard, draft, roster, ledger, month closes, receipts, founder desk, and the public claim/join/share pages*; **Watch** (Swift) owns scoring during play. "The phone is for the tee box, the desk is for the league. A draft on a 6" screen is friction we invented." So roughly a third of the inventory in §1 — `view-wizard`, `view-draft`, the pot ledger, members admin, founder desk, the desktop wings — is **out of scope for the phone by decision**, and the critique below is about the two-thirds that remain. The stack is Expo/RN, so "native patterns" below means tab + stack navigators, modal presentation, native sheets — not SwiftUI specifically.

### 7.1 Web-shaped things to replace with native patterns

1. **No navigation stack.** `switchView` is a global "show one section" switch; Post, Play, People, Schedule, Wizard, Draft and Event are all *siblings* wearing `← Back` text links, and the sheet is a single global `#sheet` whose body is replaced on every open (no stacking, no return). Native: four stacks under a tab bar — Home ▸ (Schedule, Event, Round, Tour Card…), Clubhouse ▸ (Standings, Board, Pot, Album, League, Members…), ⊕ as a **modal** flow (Post / Play / Plan as a full-screen presentation with its own stack), You ▸ (People, Settings). Sheets that are really *objects* — Tour Card, Round receipt, Scorecard, Members — should be pushed detail screens or presented sheets with detents, not one shared bottom panel. D93's own tradeoff ("deep links… do not restore the Clubhouse segment state") disappears the moment routes exist.
2. **The Clubhouse segmented control is a six-way tab inside a tab** (Standings · Board · Schedule · Pot · Album · League) where one segment (Schedule) secretly navigates away and one (Board) opens a modal on desktop but is a pane on phone. Native: Standings as the room's body, Board as its own presented conversation screen (it *is* the chat — and chat wants a keyboard-aware, bottom-anchored list, which the web composer at 1351 fights), Pot / Album / League as pushed screens or a scrolling page with sections. Keep "the room" metaphor, drop the six pills.
3. **`view-record` (the ⊕ triptych) is a menu page.** Three cards to choose after / during / before is a web hub. Native: the ⊕ presents an action sheet or a three-option cover with the Post form *already* the first thing you see (post is the 90% case; "20 seconds" is the promise on the card itself).
4. **Home is a long single lane** (doors → hero → tiles → occasion → Up Next → digest → feed) with the "make something" doors at the very top (D94) even for a member mid-season. On a phone the hero — the thing that says where you stand — is below three buttons. The team clearly went back and forth (D81 moved doors down, D94 moved them up). Native suggestion: hero first, doors become a `+` in the nav bar / the Clubhouse's empty state, tiles become a horizontal card row, feed becomes a `List` with real cell reuse.
5. **Desktop-only layouts are everywhere in CSS** (`homegrid`, `playgrid`, `postgrid`, `potgrid`, `draftgrid`, `wiz-grid`, `#roomGrid` two-column, door wings) — none of it is for iOS. The live-round screen in particular is built as two columns (scoring | side-game cards) and on a phone the game cards land *below* 18 holes of entry.
6. **Density and type**: the phone UI runs on 10–12.5px mono labels with `.14–.22em` tracking, `.fine` 13px dim helper text under most controls, and three 8.5px-labelled tiles. It reads as a designer's dashboard, not an outdoor phone app you use with one hand at the turn. Native must widen the scale: mono stays for labels but at ≥11pt Dynamic Type, hero numbers stay serif and big, and the `dim` tier gets lifted for contrast.
7. **Forms are web forms**: `input.f` grids, `type="date"` (with three CSS patches for iOS date-input width bugs, 419–430 and 1490–1494), a `<select>` for tees, `<details>` for "League rules & Pro Shop". Native: pickers, a proper date picker, a course search screen. (The wizard's nine-decision step 1 — review W1: "a step that needs eight footnotes carries too many concepts" — is moot on the phone; it is desktop work per D98.)
7b. **Uniform card rhythm.** Review F14 (`spec/design-review-2026-07-20.md`) called it "every module = same bordered card, one column — **the subtle 'AI-built' signature**. Break deliberately: standings full-bleed, hero numbers serif-oversized." The web fixed the hero; the rest of Home, Clubhouse and You are still stacks of 16-radius bordered cards. Native lists with grouped/inset sections, full-bleed tables and a few oversized serif numbers will do more for "feels like Cup Season, not a dashboard" than any single component port.
7c. **Six reactions where one thumb should live** (review F11: ~12 interactive elements per board card). The palette (`.rxpalette`, 1203) is a web hover/tray pattern; native wants a long-press picker with one visible reaction and the six named meanings behind it.
7d. **The You tab is "five screens' worth of content on one"** (review 07-16:145) — card, feedback, founder desk, trophy case, reunion whisper, record, lifetime, recent, buddies door, rivalries, season stats, league record, guide. On the phone it should be a profile header + a short grouped list that pushes to Record / Trophies / Buddies / Rivalries / Settings / How it works.
8. **Modality piled on modality**: sheet-over-sheet is emulated (`_sheetVVFit`), the toast has to be z-indexed above the sheet because "Card saved" fired invisibly behind it (1623–1625), the board is a dialog, the finish is a dialog, the install nudge is a floating bar. iOS gives you real presentation contexts; use them and drop the z-index ladder (50 / 60 / 200 / 300 / 1000 / 1100 / 99999).
9. **Boot is a browser story**: 8s watchdog, `bootStep` breadcrumbs, `forceReveal` timers, `bootResolved` guards, SW registration races, `navigator.locks` zombie tabs — all of it exists because a single page must survive Safari. Native boot is: restore session → fetch memberships → show. Keep the breadcrumb *idea* (a named boot step in the crash report) and lose the rest.
10. **The demo diorama** still lives in the classic `state` (demo seeds 3722–3775, `state.demo` default true) even though D83 retired the demo season from the product. A native app should not carry a diorama; the door's desktop wings are the only remaining showcase and they are desktop-only anyway.
11. **The `.league-only` class is a fake gate** (21 uses, inert). The real gates are `body.noleague`, `!CS.user`, `state.demo`, `phase`, `role`. Native should model these as one explicit `AppState` enum (signedOut / leagueless / forming / preseason / season / cupFinal / wrapped) × role, exactly the switch `renderHomeHero` already encodes.

### 7.2 What is genuinely cramped or broken on a phone today

- The tab bar has **four destinations in three lanes** with the ⊕ floating over the middle seam; the label "Post" is invisible (`font-size:0`) and the orientation has to *teach* it ("the ⊕ in the middle"). Fine as a brand move, but it is also a hit-target compromise (F2 fixed the 42px floor).
- The Post view's "How this round scores" calc and the point-bands table are a right column on desktop; on a phone they trail the form, so the thing that motivates the post ("+9 PTS") is below the fold until you scroll past your own inputs.
- The standings table shows five columns (rank, squad, trend sparkline, Δ wk, pts) at 11–12px in a 16px-gutter column; the climb chart and table stack vertically so "the race" is two screens tall.
- The wizard's dials are a long stack of `.setrow`s behind a "Customize" disclosure; the presets are three tall cards; the desktop aside "Your league so far" (which is the best part — it shows the bylaws forming) never appears on a phone. (Moot for the phone under D98, but it is the evidence for why the wizard went to the desk.)
- The live-round scoreboard is sticky (D85), which is right, but the per-player entry rows and the side-game cards are separate columns — a phone user scoring Wolf has to scroll between the hole and the wolf buttons.
- The sheet's body replacement means tapping a name inside a receipt loses the receipt; the code works around this by re-wiring `[data-player]`/`[data-round]` on every open (11590–11596).
- Standings row density is "approaching the 'seven numbers' problem D2 killed on round cards; prune to points + one line" (`spec/design-review-2026-07-16.md:143`) — still five columns today.
- From the friction register (`spec/friction-register-2026-07.md`): **F-007** the `memName` classic↔module bridge miss produced a live iOS `ReferenceError` that "silently breaks board name / kudos / comment rendering" — the single-file architecture's failure mode, and the strongest argument that the board must be rebuilt, not wrapped; **F-003** ~70 raw backend strings reached users (now mostly behind `humanError`); **F-005** `view-event` rendered empty (fixed, 4148–4150). Verified clean at 375px: no horizontal overflow on home/record/post/play/stats/draft; both themes render; the tester walkthrough (`spec/tester-walkthrough-v23.163.md`) times five gates — profile <2:00, join <0:30, post <1:00, read standings <0:10, zero tutorial — which are the phone app's acceptance numbers too.

### 7.3 Identity elements that MUST carry over (or it stops being Cup Season)

- **Charcoal ground, two metals, one heat axis.** Ember = live/actions, champagne = earned, never swapped; slate for stable and cooling; `pos/neg` only for performance/money. The `.earned` gold spine on a 1st-place hero is the whole reward system in one pixel.
- **Three type voices with their jobs**: mono for the scorer's tent (labels, codes, stats), serif for memory and honor (hero numbers, standings sentence, trophies, the wordmark), sans for now. Keep IBM Plex Mono and Charter/New York-class serif specifically; the serif gross number on the finish screen at 84–96pt is the app's signature frame.
- **The spine** (left accent bar) as the card grammar, radius 16 / 10 / 24, the resting-whisper shadow.
- **The roll-out easing** everywhere, and the ceremonies: POSTED stamp + thock, the finish screen (ball into cup), the split-flap rank flip, the climb re-ordering, the engraver on a fresh trophy, the month seal. These are the "storytelling standings" — they are product, not polish.
- **The Forge door** — once per device, rest frame is the logo, ember glow. On iOS this is the launch → first-run transition; keep the heat-ramp tracers and the seared wordmark, keep the once-per-device rule (`cs_forge` → UserDefaults).
- **Markers as identity** (14 named glyphs), the no-silhouette rule, the marker medallion on photos, emoji reactions with their six named meanings.
- **The voice**: bands not differentials ("beat your number by 2.4"), "the Pro", "the board", "your card", "on the books", "the ⊕", every empty state ending in a next move, two-tap "Sure?" instead of alerts, receipts behind every number (spec §16).
- **The four places** — Home · Clubhouse · ⊕ · You — and the orientation that teaches them plus "the long game / the short game" (league vs event). Tab order and names are canon (D82).
- **`v23 · <sha>` build identity** visible in settings.
